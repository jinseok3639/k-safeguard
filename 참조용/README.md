# 한국어 난독화 복원 노트북 검토

검토일: 2026-08-08

## 검토 목적

이 폴더의 한국어 난독화 문장 복원 대회 상위권 노트북 3개에서 현재 프로젝트에 재사용할 설계
아이디어를 정리했다. 노트북 원본은 `.gitignore`로 제외하며, 데이터·가중치·실행 환경과 라이선스가
함께 고정된 코드가 아니므로 구현 코드를 그대로 복사하지 않는다.

검토 대상은 다음과 같다.

1. `[private_1위] 읶겄돆 핶돆핶볶싞짂.ipynb`
2. `[private_2위] CSU_AI.ipynb`
3. `[Private_3위] 음절 단위 커스텀 토크나이저 + 다층 BiLSTM .ipynb`

1위 노트북에는 원저장소로 보이는
`https://github.com/junseok0913/Noised-Korean-Review-Deobfuscator` 링크가 있지만, 현재 파일만으로 세
노트북 전체의 코드·데이터 재사용 조건을 확정할 수 없다. 아래 내용은 아이디어 검토 기록으로만
사용한다.

## 노트북별 핵심

### 1위: 자모 복원과 문맥 모델을 결합한 다단계 파이프라인

- 완성형 음절을 초성·중성·종성으로 분해하고 어절 안의 상대 위치를 특징으로 사용한다.
- 음절별 자모를 먼저 복원한 뒤 KoELECTRA와 KoGemma 계열 모델로 문맥을 보정한다.
- 서로 다른 복원 결과를 sequence alignment, 자모 유사도, 한국어 LM perplexity로 비교한다.
- 변환 대상 문자만 교체하고 공백·문장부호·이모티콘은 원문 위치에 보존한다.
- zero-width space, 연속 공백, 문장 chunking을 별도 단계로 처리한다.

현재 프로젝트에는 **단계 분리**, **자모 단위 표현**, **비대상 문자 보존**, **후보 선택 근거 기록**을
참고할 수 있다. 반면 MLP·ELECTRA·7B 생성 모델·8B perplexity 모델의 앙상블은 재학습 없는 경량
정규화기라는 범위를 벗어난다. 독립 자모를 삭제하는 전처리도 초성체와 자모 분해 정보를 잃으므로
채택하면 안 된다.

### 2위: 자모 유사도와 사전 기반 점수제 보팅

여러 모델의 같은 위치 후보를 다음 신호로 점수화한다.

- 후보끼리 초성·중성·종성이 얼마나 일치하는지
- 입력과 후보의 초성·중성이 같거나 정의된 유사 그룹에 속하는지
- 후보가 단어 사전에 존재하는지
- 형태소 분석에서 얻은 명사 부분이 입력과 유사한지
- 이전·현재·다음 어절 중 어느 위치가 더 잘 맞는지

이 방식에서 유용한 부분은 **난독화 규칙을 즉시 역치환하지 않고 후보로 만든 뒤 여러 근거로
점수화하는 구조**다. 다만 `ㅁ→ㅇ`, `ㅃ→ㅍ` 같은 유사 그룹은 정상 단어까지 바꿀 수 있으므로
보편 치환 규칙이 아니라 검증된 후보 관계로만 써야 한다. 마지막 문자를 반복해 길이를 맞추거나
광범위한 예외 처리로 실패를 숨기는 방식도 사용하지 않는다.

### 3위: 문자 tokenizer와 양방향 sequence model

- 입력·정답의 모든 문자를 vocabulary로 구성한 문자 tokenizer를 쓴다.
- CBOW 문자 embedding과 4층 양방향 LSTM으로 문자별 복원을 시도한다.
- 난독화 입력→정답 외에 정답→정답 identity 쌍도 학습한다.
- seed와 주요 hyperparameter를 한곳에 모아 재현성을 확보하려 한다.

identity 사례는 정상 입력을 바꾸지 않는 회귀 테스트에 바로 참고할 수 있다. 문자 단위 양방향
모델은 규칙 기반 복원 성능이 부족하다는 실험 근거가 생겼을 때만 fallback 비교군으로 고려한다.
노트북은 입력·출력 길이가 달라도 dataset에 넣지만 token-wise loss는 동일 길이를 전제로 하므로,
현재 상태를 그대로 학습 레시피로 사용해서는 안 된다.

## 현재 코드와 연결

현재 `hf_repo/ko_obfuscator.py`에는 다음 기반이 이미 있다.

- `CHO`, `JUNG`, `JONG` 자모 테이블
- 완성형 음절을 인덱스로 분해하는 `_split`
- 자모 인덱스를 완성형 음절로 조합하는 `_join`
- `jamo_decompose`, `chosung`, `tensify`, `break_spacing`, `zwsp_inject` 생성 규칙
- 강도와 seed를 고정한 결정적 변형

따라서 노트북의 순방향 난독화 코드를 추가로 가져오기보다, 이 프리미티브의 **역방향 정규화
계층**을 별도로 설계하는 편이 적절하다.

| 기존 변형 | 역정규화에서 참고할 접근 | 주의점 |
|---|---|---|
| `jamo_decompose` | 호환 자모열을 음절 후보로 조합 | 음절 경계가 모호하면 원문 유지 |
| `chosung` | 사전·문맥 기반 단어 후보 생성 | 정보 손실형이므로 확정 치환 금지 |
| `tensify` | 경음→평음 후보를 만들고 문맥 점수로 선택 | 정상 된소리 단어 보호 |
| `break_spacing` | 어절 분리 후보와 원문 공백을 함께 보존 | 전역 공백 재작성 금지 |
| `zwsp_inject` | 알려진 format 문자를 명시적으로 제거 | 제거 문자와 위치 기록 |

## 권장 정규화 흐름

1. **입력 스캔**: 완성형 음절, 현대 자모, 호환 자모, 영문·숫자, 공백, 문장부호와 format 문자를
   구분하고 원문 offset을 보존한다.
2. **무손실 canonicalization**: zero-width 문자나 안전하게 조합 가능한 자모처럼 정보 손실이 없는
   축을 먼저 처리한다.
3. **후보 생성**: 된소리, 연음, 초성체와 띄어쓰기 복원은 즉시 치환하지 않고 후보 목록으로 만든다.
4. **보수적 점수화**: 원문 편집 거리, 자모 유사도, 단어 사전, 후보 간 합의를 독립 점수로 계산한다.
5. **변경 결정**: confidence가 낮거나 동률이면 원문을 유지하고, 길이 변화는 정렬 결과가 명확할
   때만 허용한다.
6. **추적 결과**: 정규화 문자열과 함께 변경 구간, 적용 규칙, confidence, 정보 손실 여부와 오류를
   반환한다.

## 벤치마크에 반영할 항목

현재 `hf_repo/benchmark.jsonl`은 clean과 다섯 난독화 기법을 포함한다. 정규화기 평가에서는 같은
`seed_id`를 기준으로 다음 네 조건을 짝지어야 한다.

1. clean + 정규화 OFF
2. obfuscated + 정규화 OFF
3. obfuscated + 정규화 ON
4. clean + 정규화 ON

필수 측정값은 공격 탐지 복원률뿐 아니라 다음을 포함한다.

- 정상 clean 입력 변경률
- benign hard-negative 오탐 변화
- 원문과 정확히 같아진 비율과 의미 보존율
- 규칙별 적용·거부 횟수와 low-confidence 비율
- 처리 지연 p50/p95/p99, 예외와 Unicode 손상 건수

## 구현 우선순위

1. 기존 `_split`·`_join`과 같은 자모 테이블을 공유하는 역정규화 모듈을 만든다.
2. zero-width 제거와 명확한 자모 재조합부터 구현하고 문자 offset 추적 테스트를 추가한다.
3. `후보 + 근거 + confidence` 결과 형식을 정의한다.
4. identity, 자모 분해, 초성체, 된소리 정상 단어, 문장부호, 한영 혼용, 길이 변화 회귀 테스트를
   만든다.
5. 기존 505개 benchmark에 정규화 OFF/ON 조건을 추가해 복원과 과수정을 함께 측정한다.
6. 실제 오류 분석 후에만 사전·형태소 scorer나 문자 sequence model의 필요성을 판단한다.

핵심은 상위권 솔루션의 대형 앙상블을 복제하는 것이 아니라 **자모 구조 기반 후보 생성, 비대상
문자 보존, 보수적 선택과 변경 추적**을 현재의 결정적 벤치마크 구조에 연결하는 것이다.
