# k-safeguard — 프로젝트 메모리

이 파일은 이 저장소에서 작업하는 모든 Claude Code 세션이 읽어야 할 컨텍스트다. 전체 배경·근거는 `README.md`에 있으니 중복 서술하지 말고 필요하면 링크만 건다.

## 한 줄 요약

한글 자모 단위 표기 난독화(된소리·연음·자모분해·초성체 등)에 대한 한국어 프롬프트 가드레일의 취약성을 실측하고, **모델 재학습 없이** 붙여서 방어력을 복원하는 정규화 미들웨어를 만드는 오픈소스 프로젝트. 팀 온돌, 2026 오픈소스 SW 개발대회 자유과제(보안·안전) 트랙 출품작.

## 현재 상태 (중요, 2026-08-13 갱신)

`src/k_safeguard`에 무손실 정규화 미들웨어(자모 조합·ZWSP 제거)와 Gateway/실행 API가 pip
패키지(`k-safeguard`, PyPI 미배포·checkout 설치만)로 구현되어 있고 `tests/`(99개) 전부 통과 확인됨.
`hf_repo/ko_obfuscator.py`에 난독화 생성기, `experiments/benchmark/`에 개별 평가 스크립트 20여 개가
있다(단, 단일 `kanana_test_suite.py`로는 아직 통합 안 됨). 모델 가중치는 저장소 밖
`D:\local llm\guardrails`에 둔다. 아래 "진행 상황 체크리스트"보다 `README.md`의 "진행 상황" 절이 더
최신이므로 그쪽을 우선 신뢰하고, 실제 파일과 최신 커밋으로 항상 재확인한다.

## 절대 다시 논쟁하지 말 것 (이미 결정됨)

- **탐지 모델(가드레일) 자체를 새로 학습해서 정면승부하지 않는다.** Kanana Safeguard-Prompt가 이미 이 자리를 선점했고, 탈옥 분류기+데이터셋도 이미 포화 상태임을 사전조사로 확인했다. 우리는 "기존 가드레일 앞단 전처리"로 포지셔닝한다.
- **핵심 산출물은 벤치마크가 아니라 미들웨어다.** 초기엔 벤치마크가 헤드라인이었으나, 대회가 기능테스트·시연영상을 중시하는 실물 오픈소스 SW 대회라는 점 때문에 주인공을 정규화 하드닝 미들웨어로 교체했다. 벤치마크·난독화 라이브러리는 미들웨어를 뒷받침하는 근거/부산물로 다룬다.
- **스코프는 한국어 표기 난독화로 한정한다.** 타 언어 우회, 멀티모달 공격, 에이전트형(도구호출·파일접근) 위협은 범위 밖. 이 프로젝트는 순수 텍스트 대화형 챗봇의 콘텐츠 분류기 레이어를 다룬다.
- **"세계 최초 발견"이라는 과장된 클레임을 쓰지 않는다.** 아래 포지셔닝 규칙을 항상 따른다.
- **브랜치/커밋 전략은 이미 확정됨** — 2인 팀 기준 경량 GitHub Flow(산출물·실험 단위 브랜치) + `영문 타입/한글 설명` 커밋 + 단위별 PR·상호 리뷰. Git Flow, 강제 브랜치 보호, semantic-release 같은 무거운 서비스용 프로세스로 바꾸지 않는다. 자세한 내용은 "Git 워크플로" 섹션 참고.

## 포지셔닝 규칙 (문서·보고서·발표자료 작성 시 강제)

문서를 쓰거나 리뷰할 때 아래 톤을 벗어나면 반드시 교정한다.

1. 취약점 발견은 "단일 분류기형 가드레일은 구조적으로 뚫린다"는 **국제적으로 이미 확립된 패턴**을 한국어·한글난독화 축에서 **처음 정량 확인**한 것으로 서술 — 세계 최초 발견 주장 금지.
2. 미들웨어는 "완전한 해법"이 아니라 **"기존 배포된 단일-분류기 가드레일에 즉시 적용 가능한 진단도구 + 임시 완화책"**으로 서술 — "가드레일을 대체한다" 같은 과장 금지.
3. "가드레일 자체가 무의미한 거 아니냐"는 반론에는 **"guardrails-by-construction(구조적 방어)은 에이전트형 위협 대응이고, 권한 제한 레버가 없는 순수 대화형 챗봇에는 분류기가 유일한 실질 방어"**라는 논지로 답한다.

## 용어집

| 용어 | 의미 |
|---|---|
| 된소리 | ㄱ→ㄲ, ㄷ→ㄸ 같은 경음화 표기 변형 |
| 연음 | 받침이 뒤 음절 초성으로 이어지는 발음을 표기에 반영하는 변형 (예: "먹을게"→"머글게") |
| 자모 분해 | 완성형 한글을 초성·중성·종성 낱자로 쪼개는 난독화 |
| 초성체 | 초성만 남기는 축약 표기 (예: "ㅇㅋ") — blind 복원 체크 대상 |
| 종성 크래밍 | 받침에 불필요한 자음을 채워 넣는 변형 |
| 게이트 실험 (gate 실험) | 방향성을 확정하기 전 1일 규모로 돌린 최소 검증 실험. 이미 완료: 된소리·쌍자음화 5/6(83%) 회피 성공, 난독화 강도와 회피율이 비례하지 않는 서열 반전 현상 발견 |
| Kanana Safeguard | 카카오가 2025.5 공개한 Apache 2.0 가드레일 3종(Safeguard-Prompt/Safeguard/Safeguard-Siren). Safeguard-Prompt가 이 프로젝트의 주 평가 대상 |
| guardrails-by-construction | 2026.2부터 업계가 이동 중인 구조적/권한기반 방어 패러다임. 에이전트형 위협 대응이며 우리 문제(콘텐츠 분류기 우회)와는 다른 레이어 |

## 계획된 산출물 (구현 시 이 구조를 따를 것)

1. **정규화 하드닝 미들웨어** (최우선) — pip-installable, 기존 가드레일 앞단 전처리 레이어. 난독화를 정규화해서 원 가드레일의 탐지 성능을 복원.
2. **벤치마크 + 평가 하네스** — 가칭 `kanana_test_suite.py`. 난독화 프롬프트를 가드레일에 통과시켜 회피율을 측정, 미들웨어의 필요성을 실측으로 뒷받침.
3. **난독화 생성 라이브러리** — 가칭 `ko_obfuscator.py`. 강도별(된소리/연음/자모분해/초성체/종성크래밍/띄어쓰기 파괴/호모글리프) 변형 프롬프트 생성기. 독립 재사용 가능한 레드팀 도구로 설계 — 미들웨어에 종속시키지 않는다.

평가 대상은 3-way 비교: (1) Kanana Safeguard-Prompt 네이티브, (2) PromptGuard/LlamaGuard 등 다국어 가드레일에 한국어 직접 투입, (3) 번역 파이프라인. 번역 파이프라인은 반드시 고전 NMT(충실도 테스트)와 LLM-as-translator(하이재킹 테스트)를 분리해서 다룬다 — 위협 구조가 다르기 때문에 하나로 뭉뚱그리면 결론이 흐려진다.

## Git 워크플로 (커밋·브랜치 규칙)

일반 서비스가 아니라 **대회 제출 마감이 있는 2인 팀 연구형 프로젝트**라는 전제로 정한 경량 규칙. Git Flow·강제 브랜치 보호·semantic-release 같은 서비스용 정석 프로세스는 오버헤드만 크므로 쓰지 않는다.

**브랜치 전략** — 경량 GitHub Flow. `main`은 항상 데모 가능한 상태로 유지하고 직접 push는 지양한다. 브랜치는 prefix로 구분하고, 위 "계획된 산출물"·"진행 상황 체크리스트"의 항목명을 그대로 브랜치명에 재사용한다.

- `feature/<산출물명>` — 예: `feature/obfuscator`, `feature/middleware`, `feature/benchmark-harness`
- `experiment/<실험명>` — 예: `experiment/gate-test`, `experiment/seed-expansion`, `experiment/translation-nmt`, `experiment/translation-llm`
- `fix/<내용>`, `docs/<내용>`

작업이 끝나면 PR → merge → 브랜치 삭제.

**커밋 컨벤션** — `type(scope): 한글 설명` 형식. 타입은 영문, 설명은 한글.

- 표준 타입: `feat`, `fix`, `docs`, `chore`, `refactor`, `test`
- 연구 특화 타입: `exp`(실험), `data`(데이터셋 추가/수정), `eval`(평가/측정 결과)
- 예시: `feat(middleware): 자모 정규화 로직 추가`, `exp(gate): 된소리 회피율 게이트 실험`, `data(seed): 시드 프롬프트 20개 추가`, `eval(benchmark): Kanana Safeguard 회피율 측정`

**PR 규칙** — 기능/실험 단위로 PR을 열고 팀원이 간단히 리뷰한 뒤 merge한다. 오타·사소한 문서 수정은 PR 없이 바로 커밋해도 된다. 실험 브랜치 PR 설명에는 결과 요약을 남긴다 — 나중에 보고서·대회 심사 근거로 그대로 재사용할 수 있다.

**태그** — 마일스톤 도달 시 태그를 남긴다. 형식: `<version>-<milestone>` (예: `v0.1.0-gate`, `v1.0.0-submission`).

**대용량 파일** — 모델 체크포인트·대용량 데이터셋은 git에 직접 커밋하지 않는다. HF Hub나 GitHub 릴리즈 첨부로 분리하고 경로만 문서에 남긴다.
